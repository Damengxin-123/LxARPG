# 原生动画图动作节点

动画蓝图的父类需要为 `LxAnimInstanceBase`（角色动画类型基类）。在 AnimGraph（动画图表）右键搜索“基础动作”“近战动作”“远程动作”“防御动作”“动画动作缓存”“动作骨骼分层混合”“动作姿势混合堆栈”，或从“角色动画 / 动作”分类添加。

## 推荐连接方式

```text
闲置、走路、跑步等基础动作 → 动画动作缓存 ──→ 基础动作
                                                动作骨骼分层混合 → 动作姿势混合堆栈 → 输出姿势
近战、远程、防御等技能动作 → 动画动作缓存 ──→ 技能动作
```

整条链路输出标准 Pose（姿势），兼容原生姿势输出。动画序列只是资源引用，不能表达已经进行的骨骼分层、曲线和动画属性混合。原生 `Blend Stack`（混合堆栈）负责播放并混合动画资源，不能直接接在骨骼分层姿势之后；此处使用新增的“动作姿势混合堆栈”。

基础和技能分别使用一个缓存，避免基础运动与技能竞争同一个缓存输入。新增功能不自动改写已有动画蓝图资产；旧动作节点和原有连线继续可用。

## 动作选项

- **是否使用骨骼混合**：默认开启。技能动作由“动作骨骼分层混合”按配置的骨骼分支覆盖基础姿势；关闭后，该技能匹配时覆盖全身。基础输入始终作为底层姿势。此开关由新增分层节点消费，直接连接原生分层节点时仍使用原生节点的权重与配置。
- **是否接收动画通知**：默认开启，保留已有行为。关闭后，该节点的普通通知及通知状态不再进入正常分发；切换前已经开始的通知状态仍由引擎结束清理。其他节点使用相同序列时不受影响。
- 蒙太奇的关闭开关同时覆盖排队通知与分支点通知。运行时仅创建实例私有的无通知蒙太奇描述，继续共享底层动画序列，不复制压缩动画数据、不修改原始资产。

## 动画动作缓存

右键节点选择“添加动作输入”，或在详情的“候选动作”数组中增删输入。每个输入连接一个动作节点，允许经过重路由。技能 ID 精确匹配的专用动作优先于未指定 ID 的通用动作；相同优先级按输入从前到后选择。

缓存只推进选中的播放器。未选中的候选不会为了检查匹配而播放，也不会发出通知。循环动作持续推进，非循环动作播放结束后保持末帧；“无匹配时保持动作”默认开启，没有新匹配时继续保持原播放器，关闭该项则输出参考姿势。

缓存保留的是动作选择和播放进度，不是每帧重新开始的动画，也不是原生 `Save Cached Pose`（保存缓存姿势）的别名。同一技能的新播放请求仍从头开始；切到其他候选后再返回也会重新开始。开启保持时，蒙太奇实例关闭自动淡出并保持末帧，由动作信号停止或缓存选择改变结束；不要把蒙太奇自动淡出回调作为这类缓存动作唯一的技能完成来源。

技能通道停止时，缓存可以保留最后动作，但其“仍在执行”状态已经失效。下游分层节点据此恢复基础动作，不会因保留缓存而继续攻击或格挡。

## 动作骨骼分层混合

“基础动作”和“技能动作”各连接一个动作缓存。在“骨骼分层设置”内填写起始骨骼与分支深度，例如人形骨架的 `spine_01`（第一节脊柱）与深度 1。使用实际角色骨架中的骨骼名称，编译会检查名称。未配置分支时给出警告，分层动作不会覆盖任何骨骼。

有效技能开启骨骼混合时复用引擎原生逐骨骼混合；关闭时仅求值全身技能动作；没有有效技能时自动使用基础动作。内部保留原生曲线、动画属性和根运动权重处理。

## 动作姿势混合堆栈

输入连接“动作骨骼分层混合”，仅需基础动作时也可直接连接“动画动作缓存”。不能在这段连接中插入丢失动作描述的原生混合节点；编译器会提示错误。输出可继续接原生姿势处理节点或最终输出。

默认过渡时间 0.2 秒、最多 4 个历史姿势层。基础动作变化、技能开始与结束、同技能新请求、分层与全身模式变化都会触发过渡。快速连续切换时继续混合已有历史，超出层数会折叠为最近输出，避免无界增长。过渡时间为零表示立即切换。

历史保存的是退出时的姿势、曲线及动画属性，不继续推进旧播放器，因此不会重复旧动作通知。骨骼缓存或 LOD 改变时丢弃历史姿势。此节点平滑视觉姿势，角色位移和根运动仍由当前有效动画及原有移动系统处理，不对历史位移进行重放。

## 配置

- 基础动作：选择运动类型与动画资源。基础信号按角色真实运动状态采样，地面运动使用行为树配置的低、中、高速类型；静止时为闲置或警惕，空中保持跳跃、滞空与落地信号。
- 近战、远程、防御：节点固定其动作类型，可额外填写“技能ID”。留空只比较类型，填写后同时比较类型与完整技能ID，不进行父标签匹配。
- 支持动画序列、动画合成、混合空间和单插槽轨道的蒙太奇。骨架不兼容、缺失资源或错误父类会在动画蓝图编译时提示。
- 混合空间使用“混合空间坐标”，可展开为引脚并接入速度、方向等参数；坐标单位和轴含义由混合空间资源决定。
- 节点不提供手填播放速率。移动沿用实际速度÷600，并限制在0.1～3；技能默认按原始速率播放，不再按配置的释放时间缩放。动画处理组件的蓝图速率转换扩展继续生效，实际执行点跟随通知移动。

## 独立通道与混合

动画实例分别保存“基础动作运动类型”“攻击动作运动类型”“当前攻击技能ID”。基础信号和攻击信号不会互相覆盖。已有“当前运动类型”继续保留行为树语义，新的动作节点读取独立通道。

基础动作节点的 Pose（姿势）输出可直接连接 Output Pose（输出姿势）。同时播放时，将基础动作接到 Layered Blend per Bone（逐骨骼分层混合）的基础姿势，攻击动作接到分层姿势，然后在原生分层节点中配置起始骨骼、分支深度或混合遮罩。

分层和普通 Blend（混合）的权重仍由原生节点控制。可调用“动作节点是否匹配”，传入相同类型及技能ID，驱动动作层权重；通过布尔混合节点的过渡时间或平滑权重控制切换。通用节点与技能专用节点可能同时匹配，同类方案的优先级由动画图连线决定。

序列或混合空间失配后停止推进并保留末帧供外部过渡，首次未匹配时输出参考姿势；进入新动作或收到同技能新播放请求时从头播放。不要让失配节点持续以满权重覆盖基础动作。

## 技能来源

技能的实际创建由动画通知驱动，详见 [技能动画通知说明](../LxARPG/LxSource/Model/Skill/技能动画通知说明.md)。在动画序列的释放帧添加“角色动作通知”，通知名称设为“技能释放”；动画播放完毕自动结束，也可以添加“技能结束”通知提前结束后摇。动作节点须勾选“是否接收动画通知”。

AI释放技能时，近战、远程或防御行为的运动类型优先作为攻击类型；玩家技能可在技能蓝图的“技能 / 动画 / 攻击动作类型”配置类型。技能物品ID随原有网络广播传入动画通道。原有近身攻击、格挡也会发出通用动作请求，并避免覆盖已经存在的技能动作速率。

## 蒙太奇

蒙太奇通过自身插槽及原生蒙太奇实例播放，保留段落、通知和根运动的引擎处理方式。当前节点支持单插槽轨道；多个身体部位通过外部逐骨骼分层节点组织。循环由蒙太奇段落连接决定，序列循环标记不改写蒙太奇段落。

基础和攻击蒙太奇需要同时播放时，应使用不同的 Slot Group（插槽组）；同组蒙太奇仍遵循引擎的互斥规则。节点首次参与图更新后，在下一次游戏线程预更新启动蒙太奇，存在一帧启动延迟。不要同时用旧的直接播放蒙太奇入口和新节点驱动同一动作。

## 验证

`Automation RunTests LxARPG.Animation.ActionNodes` 在临时动画蓝图中编译节点并实际推进骨骼网格动画，覆盖动画序列、动画合成、混合空间、蒙太奇、普通混合、逐骨骼分层混合、技能精确匹配、通道独立、自动速率、重复请求及停止。测试不修改用户动画蓝图或动画资源。

`Automation RunTests LxARPG.Animation.ActionFlow` 在临时动画蓝图中连接“动作 → 缓存 → 骨骼分层 → 姿势堆栈 → 输出”，使用可验证骨骼位移和旋转的临时动画，检查缓存优先级、无匹配保持、分层与全身覆盖、技能结束恢复、通知开关、蒙太奇分支点、同技能重放、连续切换和过渡层数上限。

图节点位于 `LxARPGAnimGraph`（UncookedOnly）模块，运行时播放器位于 `LxARPG` 模块。
