# 技能动画通知

技能不再配置“技能释放时间”，也不再按时间的百分之五十创建技能实体。提交释放输入后，释放模块先取得占用并发送技能物品 ID 和本次释放编号，动画系统按原有动作节点选择动画。

## 在动画中设置

1. 打开 Animation Sequence（动画序列），找到 Notifies（通知）轨道，在需要生效的帧右键，选择 Add Notify（添加通知）→“角色动作通知”。
2. 选中通知，将“通知名称”设为“技能释放”。同一角色的本次释放只消费第一个有效释放通知，重复通知不会重复创建实体。
3. 动作节点勾选“是否接收动画通知”。通知的 Trigger Chance（触发概率）设为 1，并保留 Trigger on Dedicated Server（在专用服务器触发）。避免对技能通知设置距离或 LOD 过滤。
4. 普通非循环动画会在实际播放到末尾时结束本次动画占用。需要提前结束后摇时，再添加一个“角色动作通知”，名称设为“技能结束”。循环动画及自行循环段落的蒙太奇应明确设置结束通知，或者由输入停止技能。

也兼容名为“技能释放”“技能结束”的 Skeleton Notify（骨架通知），使用 Queued（排队）方式。需要 Montage Branching Point（蒙太奇分支点）时，使用上述“角色动作通知”。不要使用 Notify State（通知状态）充当单次释放点。

无释放通知的动画不会创建技能；非循环播放结束后会取消尚未执行的释放，不补发实体。资源缺失、没有匹配动作或无限循环且没有结束通知时，不能依靠自然结束，需要修正动画配置或取消当前技能。基础脚步音效仍使用 Play Sound（播放声音）或现有脚步通知。

## 回传路径

动作节点保存播放来源 → 动画蓝图基类统一收集 → 动画处理组件 → 数据中转组件 → 战斗组件 → 技能释放模块 → 原有技能蓝图释放事件。

动画蓝图继承“角色动画类型基类”即可接入，无需为每个技能手动连接通知。可实现“收到角色动画通知”观察通知名称、技能 ID、释放编号及是否动作通道；实际技能业务由原生回传链路执行，不要在该观察事件里再次创建实体。节点中的通知身份随缓存保存，不能用接收时的当前技能来替换。

直接释放、蓄力结束和持续释放的启动均等待动画释放通知。持续技能在动画结束后仍保持技能运行，直到停止或取消；勾选“等待显式结束释放”的技能也保留原有显式结束规则。技能 CD 暂时停用，动画自然结束或收到结束通知后即可再次释放，取消也不再记录冷却。按住直接释放技能时，快捷栏逐帧检查释放占用，不再使用冷却定时器。

只有权威端接收的动画通知能执行技能，客户端不通过 RPC 上报命中帧。施法期间服务端临时持续刷新骨骼并关闭更新频率优化，使离屏角色的序列通知和技能锚点继续更新；停止动画后恢复原设置。动画处理组件对播放速率的调整会同步改变通知发生时间。

## 验证

自动化测试 `LxARPG.Animation.SkillEvents` 使用临时动画蓝图和实际骨骼网格，覆盖序列、合成、蒙太奇分支点、通知回传、自然结束、显式结束、重复通知、过期通知、取消、蓄力、持续释放及通知开关。测试不修改项目动画资产；现有技能动画须按上述步骤标记释放帧。
