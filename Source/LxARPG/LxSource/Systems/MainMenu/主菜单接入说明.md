# 主菜单接入

主菜单使用实际关卡作为背景。左侧提供选择地图存档、设置和退出，角色两侧切换独立角色档。选择地图档后点击“进入游戏”，将该角色的个人进度与地图单位状态组合为正式会话。

## 启动

- `GameDefaultMap`（游戏默认地图）与 `EditorStartupMap`（编辑器启动地图）统一使用 `/Game/项目内容/关卡/总关卡`。在编辑器打开“总关卡”直接运行，首先显示主菜单。
- 总关卡继续使用 `ALxARPGGameMode`（ARPG 游戏模式）及其现有蓝图。启动时恢复最后使用角色的位置与外观，锁定角色输入；选择存档后在同一个世界实例中进入正式游玩，无须先打开独立菜单关卡。
- “主菜单”控件蓝图位于 `/Game/项目内容/UI界面/主菜单/主菜单`，父类为 `ULxMainMenuWidget`（主菜单界面）；同目录的“设置”蓝图继承 `ULxSettingsWidget`（设置界面）。两个 C++ 类型只处理逻辑与通知，全部布局在蓝图子类的 Designer（设计器）中完成，空蓝图不会回退到原生布局。
- 项目设置中的“主菜单设置”可配置总关卡、旧档兼容角色、正式游戏模式、界面类型、展示待机动画、预览环境数据层及镜头参数。
- 启动地图与初始角色配置仍通过 `Source/LxARPGEditor/Scripts/创建主菜单.py` 创建。界面布局与事件图由 `LxMainMenuLayout` 编辑器命令工具生成，见下文。

仓库原有规则不跟踪 Content 资产及大多数配置文件。中文菜单资产和启动配置已生成在本地，源码提交包含可复现这些内容的创建脚本。

## 界面外观与角色身份

主界面通过控件蓝图排布左侧的“打开存档”“设置”“退出游戏”、角色切换按钮与种族昵称信息。尺寸、锚点、颜色、装饰、遮罩、控件层级和动画均由蓝图子类决定。C++ 不再构造 Slate（界面框架）布局，也不通过固定控件名称或 `BindWidget`（绑定控件）限制设计器。只有一个角色时，蓝图根据“是否可切换角色”禁用切换按钮。

原有程序绘制的装饰以编辑期烘焙的 9 张透明纹理保存到 `/Game/项目内容/UI界面/主菜单/图像`：侧栏、按钮、按钮高亮、切换框、切换框高亮、铭牌、弹窗、小按钮、小按钮高亮。可重新导入的 PNG 源图保存在 `Content/项目内容/UI界面/主菜单/图像/源图`。蓝图引用这些纹理，恢复原有的位置、字号、双金边、角饰、高亮、角色铭牌和设置排列；打开弹窗时保留遮罩后方的主界面。原生几何绘制仅用于编辑器烘焙工具，运行时没有程序画框依赖，所有布局仍在蓝图子类中。

“新建角色”入口位于“打开存档”面板内，输入昵称并选择数据表配置的种族。当前只提供人类，使用现有“测试角色-玩家控制角色”。昵称读取角色档案名称，种族名称按存档种族从配置表读取。背景和人物继续使用当前存档对应的真实游戏场景及角色资源。

## C++ 逻辑与蓝图布局接入

`ULxMainMenuSubsystem`（主菜单流程）负责存档、角色预览和进入游戏；主菜单界面基类负责面板状态、操作校验与蓝图通知，在构造时订阅数据源、卸载时解绑，重新挂载后恢复监听。

| 蓝图入口 | 接入方式 |
| --- | --- |
| `ReceiveMenuChanged`（主菜单数据更新） | 通过“获取角色昵称”“获取角色种族文本”“获取菜单提示”“获取地图存档列表”等函数更新显示，根据“菜单是否忙碌”“是否可进入游戏”等状态控制按钮与加载遮罩。 |
| `ReceivePanelChanged`（主菜单面板改变） | 自行设置可见性或 `WidgetSwitcher`（控件切换器）。`ELxMainMenuPanel`（主菜单面板）依次为主界面、地图存档、设置、新建角色，对应索引 0～3。 |
| 按钮 `OnClicked`（点击时） | 调用“打开地图存档面板”“打开设置面板”“打开新建角色面板”“返回主界面”“切换角色”“进入选中存档”等函数。 |
| 地图存档列表 | 用“获取地图选项”生成可滚动的“存档条目”蓝图，显示存档名称、保存时间和选中状态；点击时调用“按索引选择地图存档”。自定义列表也可使用完整结构与稳定 ID（标识符）接口。 |
| 种族下拉框 | 用“获取种族选项”填充，选择索引交给“按种族索引新建角色”。 |
| 设置子控件 | 在每次 `Event Construct`（构造事件）调用“注册设置界面”，传入布局中的设置实例。卸载会清空注册，不能只在首次初始化时注册。打开时开始新的编辑；应用或取消后回到主界面；直接返回也会丢弃未应用草稿。 |

动态创建显示控件后，可调用“刷新主菜单显示”补发数据。蓝图通过基类函数修改状态，无需复制存档、配置保存或流程校验逻辑。设置界面也可独立使用，由宿主监听“请求关闭设置”决定移除或切换页面。

编译 `LxARPGEditor`（项目编辑器）后，通过 `UnrealEditor-Cmd.exe`（虚幻编辑器命令程序）执行项目并传入 `-run=LxMainMenuLayout -Apply -unattended -nullrhi -nosplash`，可创建或填充“主菜单”和“设置”两个中文控件蓝图；去掉 `-Apply` 仅验证。布局和调用 C++ 的事件图保存在蓝图资产内。已有设计器控件或已有连线逻辑的蓝图会保留并进行编译检查，不会被生成器覆盖；首次修改前的备份位于 `Saved/MainMenuLayout/Before/Content`。

生成基础布局后，再执行 `-run=LxMainMenuLayout -RestoreAppearance -AllowCommandletRendering -RenderOffscreen -unattended -nosplash`，烘焙图像并恢复生成器模板的旧版外观与滚动存档列表。该操作只接受匹配模板结构的资产，修改前备份至 `Saved/MainMenuLayout/BeforeAppearance/Content`；同一备份不会被重复执行覆盖。`-RestoreAppearance`（恢复外观）会恢复默认生成器布局，修改过外观后应按需使用。纹理烘焙需要真实渲染，不能同时传入 `-NullRHI`（无渲染接口）。

已有自定义界面保留布局，把 Parent Class（父类）设为对应 C++ 类型，再连接上述事件与调用函数；“主菜单设置 → 主菜单界面类型”应指向主菜单蓝图。

“存档条目”控件蓝图位于 `/Game/项目内容/UI界面/主菜单/存档条目`，条目布局和显示事件均可在蓝图中编辑。主菜单在收到数据通知后重建滚动列表，业务选择仍交给 C++ 基类处理。装饰纹理、条目布局与设置控件的排列都可直接在蓝图设计器中调整，无需修改运行时 C++。

## 种族与玩家角色类型

- 配置表：`/Game/项目内容/数据表格/角色种族表`，Row Structure（行结构）为 `FLxCharacterRaceConfig`（角色种族配置），字段为种族、种族名称和玩家角色类型。
- 配置入口：打开 `/Game/项目内容/数据资产/类型_数据表格管理对象`，在“类默认值 → 数据表配置|角色 → 角色种族表”设置此表。每个种族只能出现一次，角色类型必须是可实例化的 `ALxPlayerCharacter`（玩家角色）子类。
- 新建角色从所选种族查询角色类，将种族与类型缓存写入独立角色档。加载时以种族表为准解析类型，再生成角色、恢复背包/任务/职业/装备并由控制器接管。
- 蓝图“新建角色”新增 Race（种族）输入，默认人类；“获取可选角色种族”提供配置选项。配置不完整、重复或种族未配置时拒绝创建/进入并显示原因。
- 旧存档没有种族时，从原角色蓝图默认种族迁移；默认种族也为空时，必须能通过唯一的原角色类映射确定种族。仅更早的无角色类旧档使用“默认角色类型”辅助迁移，不会把未知种族静默改为人类。迁移在内存中进行，正常保存时才写回。
- 执行 `Source/LxARPGEditor/Scripts/配置角色种族.py` 可重建人类表配置与管理器引用；已有其他种族行会保留。

## 存档与位置

- 目录前缀默认为 `LxARPG_Profiles`；与旧 `LxARPG_AutoSave` 文件并存。首次使用迁移旧档，保留旧文件。
- 每个角色使用独立 GUID（全局唯一标识符），同一种角色可建立多个档案。标签用于角色档内部的业务记录，不能代替档案实例身份。
- 角色档保存个人进度、角色种族、角色类型缓存、关卡路径、位置、朝向、主体骨骼网格及材质。新角色首次进入时使用角色蓝图的默认内容。
- 地图档不包含玩家记录，保留现有地图存档组件支持的交互对象及固定刷怪点状态。基础地图资源共用。
- 同一角色跨地图档共用最后保存位置；若脚下没有地面或被阻挡，正式生成时回退到出生点。当前版本不分别保存每个“角色＋地图档”的位置。
- 每次保存先写入角色和地图新快照，再更新交替使用的目录副本。恢复时选择最新且完整的提交；被淘汰目录独占的快照会清理，保留当前和上一份提交所需文件。
- 菜单浏览不修改最后游玩记录，正式角色恢复成功后才更新该记录。关卡跳转或组件恢复失败会阻止不完整进度覆盖旧档。

地图单位的持久化范围沿用现有系统：机关、宝箱、商店、仓库、固定刷怪点。固定刷怪点目前保存种类和存活数量；单个怪物的位置、生命值、动态销毁对象的重建不是本次菜单功能新增的内容。

## 同一总关卡的菜单状态与游玩状态

`ALxARPGGameMode`（ARPG 游戏模式）在初始化阶段进入菜单状态，拦截默认出生及登录事件触发的角色生成，暂不分发正式 BeginPlay（开始运行）。菜单按角色存档位置显示骨骼网格、镜头和流送源；控制器只接收界面输入，并锁定移动与视角，因此战斗、刷怪和角色操控不会提前开始。

菜单只读保护同时拦截存档注册、采集、缓存更新和落盘。正式进入时先绑定选中的角色与地图档案，再复用当前总关卡及已加载的展示区域，分发 BeginPlay、恢复地图状态并生成正式玩家；恢复成功后撤下菜单、解除输入锁定并交还控制权。

游戏中返回主菜单或恢复失败时，会重新载入同一总关卡，以清理已经运行的战斗、刷怪和存档组件。角色切换只改变总关卡内的展示位置；旧档若记录了其他测试地图，位置回退到总关卡出生点。旧“主菜单”地图和 `ALxMainMenuGameMode`（主菜单游戏模式）仅保留兼容，不再作为正常启动入口。

`ULxMainMenuSubsystem`（主菜单流程）提供中文蓝图接口：切换角色、选择地图存档、新建角色、新建地图存档、进入选中存档、保存并返回主菜单、保存并退出游戏。游戏中的返回菜单入口可以调用“保存并返回主菜单”；保存失败时返回假并保留当前会话。

旧存档通过上述种族兼容规则解析玩家类型；没有位置或最近游玩索引时，使用配置的关卡和出生点。不同骨架角色需要配置匹配的展示动画；不兼容的动画不会强制应用。

## 全局设置

`ULxSettingsWidget`（设置界面）管理整体画质、垂直同步、主音量、视角灵敏度和垂直视角反转的草稿。每次打开调用“开始编辑设置”；控件输入调用“设置待应用主音量”等函数，`ReceiveSettingsChanged`（设置编辑值已更新）通知蓝图用 `FLxMenuSettingsValues`（设置编辑值）同步显示。“是否存在未应用设置”可控制应用按钮。

“应用设置”成功后才保存配置并通知关闭；“取消设置”还原本次打开时的草稿，不修改运行配置或写文件。编辑中重建显示控件保留草稿，同值输入不会循环通知。音量限制为 0～1，灵敏度限制为 0.1～3，非有限输入恢复默认值；画质 -1 保留自定义独立画质，0～4 为低、中、高、极高、影视级。音量与操作偏好位于 `GameUserSettings.ini` 的独立节中，不进入角色或地图存档，画面设置不改动分辨率。布局与交互反馈均由蓝图子类实现。

## 验证

- `LxARPG.Menu.UI` 包含四个界面测试：设置编辑与取消隔离真实配置、同值回调不循环开启编辑、输入范围与非有限值、重构保留草稿、无原生默认布局、蓝图通知、重复构造去重、卸载解绑与重挂，以及设置关闭回到主界面。`BlueprintInteraction`（蓝图交互）还会加载实际的“主菜单”和“设置”蓝图，广播按钮和滑条事件，检查页面切换、草稿更新与取消连线；运行前应先生成布局资产。这组测试不应用用户设置，也不创建角色地图档。
- 编辑器自动化过滤器 `LxARPG.Menu`：角色和地图隔离、双目录恢复、旧档迁移、菜单只读、未启动玩法的世界生命周期，以及 `LxARPG.Menu.Race` 的种族表配置、旧档解析和真实资产序列化。
- `LxARPG.Menu.RuntimeFlow` 在独立游戏运行：新建人类角色、拒绝未配置种族、同一总关卡切换角色、新建地图、原地进入正式会话、保存返回和再次读档恢复背包进度，并检查菜单输入锁定、正式输入解锁及保存位置预览。必须提供 `-LxMenuSavePrefix=LxMenuSmoke_唯一值 -LxMenuIgnoreLegacy`，测试拒绝接触普通存档前缀。
- 真实渲染使用 `-game -RenderOffscreen`；纯逻辑检查可使用 `-game -NullRHI`。自动化入口为 `-ExecCmds="Automation RunTests LxARPG.Menu.RuntimeFlow" -TestExit="Automation Test Queue Empty"`。
- 渲染截图输出至 `Saved/Automation/MainMenu`，测试目录和旧游戏存档相互隔离。
- `LxARPG.Menu.PIEFlow` 在编辑器自动启动总关卡的 PIE（编辑器内运行），验证菜单启动隔离、同世界进入游戏和输入恢复；同样必须使用上述隔离存档参数，测试结束会自动退出 PIE。
- PIE 测试精确登记了总关卡现有的“城镇-地形_WaterBrushManager”跨运行时数据层引用“城镇-地形”错误，不忽略其他地图错误；地图修复后需删除对应预期错误登记。
