# 存档接入

`ULxGameInstanceSubsystem`（游戏实例全局子系统）持有 `ULxSaveManager`（存档管理模块）。管理器读取文件、按标签索引数据，并统一保存。角色和交互对象上的组件只做属性转换、查询与恢复，不单独读写文件。

## 保存范围

| 对象 | 保存属性 |
| --- | --- |
| 玩家 | 存档标签、背包容量与槽位、装备槽位、物品数量与实例词条、任务系列/任务标签与状态、职业标签/等级/经验/升级权限 |
| 机关 | 对象标签、功能节点 GUID、交互状态、机关开关状态 |
| 宝箱 | 对象标签、功能节点 GUID、交互状态、物品槽位、是否已经通知领取完成 |
| 商店 | 对象标签、功能节点 GUID、交互状态、商品库存槽位、出售与收购倍率 |
| 仓库 | 对象标签、功能节点 GUID、交互状态、仓库物品槽位 |

空槽和物品排列会保留；对象指针、界面、角色位置和其他未列出的战斗数据不进入记录。物品和职业的静态定义通过标签重建。交互中的临时占用状态恢复为可交互，不恢复旧会话。

## 编辑器配置

1. `ALxPlayerCharacter`（玩家角色）已经自动挂载“玩家存档”组件。默认使用 `CharacterIDTag`（角色ID标签）；需要区分同类型的多个玩家时，在组件上设置不同的 `SaveID`（存档ID标签）。
2. 在关卡实例的 `ULxInteractableComponent`（交互提供组件）中设置 `InteractionIDTag`（交互对象ID标签）。建议使用类似“存档.交互对象.村庄.宝箱一”的 Gameplay Tag（游戏玩法标签）。同一份存档内，跨地图的交互对象标签也必须唯一且长期保持稳定。
3. 包含机关、宝箱、商店或仓库功能的交互组件会自动创建“交互存档”组件。每个交互功能使用资产内原有节点 GUID 定位，调整节点显示顺序不会串档；重新创建节点会产生新的身份。
4. 在项目设置的“游戏设置 / 存档”中配置 `SaveSlotName`（存档槽名称）和 `SaveUserIndex`（存档用户索引）。默认槽为 `LxARPG_AutoSave`，Windows 本地开发运行时位于项目的 `Saved/SaveGames`。

未配置有效ID的对象会记录警告并跳过持久化；重复ID会拒绝后注册的对象。动态生成的交互对象需要由生成者分配可重复使用的稳定标签，本模块不负责重建已销毁的场景对象。

## 生命周期与蓝图接口

- 子系统 `Initialize`（初始化）在静态数据管理器就绪后发出“加载存档事件”，同步完成加载。独立游戏和 PIE（编辑器中运行）都早于玩家查询存档。
- 玩家默认数据初始化结束、交互功能树初始化结束后，存档组件注册并恢复对象自身数据。首次启动无存档时保留默认配置。
- `OnWorldBeginTearDown`（世界开始拆除）在对象清理前采集状态并发出“保存存档事件”。普通切图保留内存中其他地图的数据。
- 流式关卡卸载前缓存其对象；玩家和交互组件也在业务模块结束之前缓存并注销。对象清理后的空数据不会再次覆盖快照。
- 子系统 `Deinitialize`（反初始化）最终只落盘缓存，不再访问已清理对象。
- 蓝图可通过“获取存档管理模块”查询“存档是否已加载”，通过子系统的“请求保存存档”主动保存，并监听“存档加载完成 / 存档保存完成”的成功结果。启动事件早于场景蓝图，场景就绪后请查询状态。
- “请求加载存档”是幂等操作，已经加载时不会从磁盘回滚当前游戏进度；当前版本为单槽自动存档，不提供运行中切换存档槽。

本地存档只采集权威对象；联机客户端不以自身副本覆盖服务端进度。多玩家若共享同一管理器，需要配置不同玩家存档标签。

## 文件与异常处理

文件包含格式标识、封套版本、数据长度、CRC 校验码以及引擎 `USaveGame`（存档对象）序列化结果，应通过本模块加载，不直接调用通用“从槽位加载游戏”。坏档、截断数据和不支持的版本会加载失败，自动保存不会覆盖原文件。写盘失败会保留内存数据并回报失败。

角色恢复先校验背包、装备、任务、职业四类数据；物品配置缺失等错误会阻止注册，保留原存档。恢复使用专用属性接口，不走接取/提交任务、领取宝箱、学习职业或增加经验流程。装备及职业效果由现有模块刷新来源效果，不把运行时效果对象存进文件。
